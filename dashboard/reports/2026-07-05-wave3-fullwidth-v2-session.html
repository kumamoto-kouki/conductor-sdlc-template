2026-07-05 振り返り：Wave3ポータル化・全幅化・レイアウトv2・体制拡張の段階反映

前レポート（2026-07-04-astro7-maximize-session.md）以降のまとまり。ダッシュボードは1ページの生成物から、目次ナビ・3層報告・別ページ概要を持つ小さなサイトへ変わった。

何を実装したか

  1. Wave 3：reports/steering の content collections によるポータル化（18ページ生成）＋アイランド対話性（ボードフィルタ・用語集検索・ダークトグル、vanilla JSのみ）。委譲→レビューAPPROVED→是正2件→統合
  2. 全幅化＋レスポンシブ：max-w-[1080px] 撤廃。390/768/1440/2560px で実描画検証。390px で実害のあった横はみ出し2件（コンポーネント表・Markdown由来の素の表）を実機検証で発見し是正
  3. レイアウトv2（PO指示8項目）：概要の別ページ分離・需要側3役の体制図反映・報告の3層化（対会社→部内→チーム内）・最小フォント14px・favicon・レフトナビ・更新表示の項目単位チップ化・文章規範のsteering化（writing-standards.md）
  4. 体制拡張の段階反映①：代弁ペルソナ3役（エンドユーザー/現場/ステークホルダー）を候補ロスターへ登録、フォワードエンジニアリング強化3方向の発動判断基準を full-sdlc.md へ追記。実投入は次の実プロジェクト、機構化は2回効いてから
  5. 小タスク：青リングの本来色化（ring-line へ4箇所）・SSG PoCブランチ2本と残骸 master の撤去・Serena導入→PO判断で即日除外（判断材料は progress.log に残置）

詰まった点・繰り返した判断

  • 独立レビューにも盲点がある。統括の受理時スクショ目視は省略しない：Wave3はレビューAPPROVED後の統合時に、統括自身のスクリーンショット確認でコードブロック判読不能（グローバル code チップCSSがshiki内部へ波及）を発見した。レビュアーは同ページのMermaid描画は見たが、下方のコードブロックまで目視していなかった。「見た目に関わる変更は実ブラウザ描画＋スクリーンショットで受理する」の実行主体はレビュアーだけでなく統括の受理段階にも要る。
  • .claude/settings.json のセッション由来汚染（2回発生→正本へ格上げ済み）：サブエージェントの許可プロンプト応答が、使い捨てコマンドのallowルール・git commit * の包括許可・defaultMode変更としてガードレールファイルに書き込まれる。受理手順（delegation.md §3）に汚染チェックを追加した。
  • ベース是正ガードのマーカー粒度が粗いと、古いベースを検知できない：全幅化Makerのworktreeが直前コミット（77acc10）より古いmainから作られたが、ガードのマーカー（機能の存在確認）は満たしてしまい、生成物ファイルでマージコンフリクトになった。ソースは競合せず、生成物のコンフリクトは再ビルドで解決できた（手動マージしない）。次回から着手前ガードのマーカーは「直近コミットの内容」由来にする（1回目のため報告に留める。再発したら delegation.md へ格上げ）。
  • テンプレート自身が自分の起動チェックリストを未適用だった：core.hooksPath が本リポジトリで未設定＝pre-commitフックが一度も有効でなかった。steering がWave3でビルド入力になったことで露見した（role-catalog.md 変更時に生成物が再生成されず）。READMEに書いてある項目でも、書いた時点で自リポジトリに適用しなければ絵に描いた餅になる。
  • 「情報量を減らさない」の証明は、ページ分割後はページ横断の合計で行う：概要の別ページ化で本体ページ単体の要素数は減る（verifyのチェック4は⚠を出す）。移動と削除を区別するには、移動前の単体 vs 移動後の合計＋消失トークンの個別分類（移動先に実在／指示による差し替え／無断削除）まで要る。レビュアーが独立に再計数し、消失7トークン全てを分類して「無断削除ゼロ」を確定した。
  • 規範は実装より先にコミットして同じwaveから効かせる：文章規範（writing-standards.md）をレイアウトv2の委譲前にsteeringへコミットし、Makerの新規文言に適用させた。後から書くと「既存文の一括書き換えをどうするか」問題だけが残る（今回は「新規と触れた文から適用」を規範自体に明記）。
  • フォント床の変更は「最小値の機械証明」で受理する：最小14px指定は、全ページ×複数幅の computed font-size をCDPで走査した最小値の実出力で確認した。ソースgrep（arbitrary px値ゼロ）だけではSVG内やinline styleを見落とす。

.claude/rules/ / 正本への格上げ

  • 済み：settings.json 汚染チェックを delegation.md §3 に追加（2回発生）
  • 候補（1回目・様子見）：着手前ガードのマーカーを直近コミット由来にする／統括の受理段階でのスクショ目視の明文化
