# reports/ — セッション報告・作業メモ

タスク・スペックの実装がひと区切りついたタイミングで、軽量な中間レポートを書ける場所。**恒久記録の経由地にはしない**——恒久化したい内容は、書いた時点で然るべき正本へ直接記録する（下記「恒久内容の行き先」）。

## 位置づけ

- ここに置くレポートは**セッション報告・作業メモ**であり、読み返される前提を置かない。書いた本人以外が後で参照する必要がある内容は、ここに留めない。
- 中間レポートは**随時削除してよい**。次のセッションで内容が古くなった、恒久化すべき内容をすでに正本へ書き終えた、などの理由で消してかまわない。

## 恒久内容の行き先

書いた内容が次のいずれかに該当するなら、レポートに留め置かず該当の正本へ直接書く。

| 恒久内容の種類                         | 書く場所                                                             |
| -------------------------------------- | -------------------------------------------------------------------- |
| バージョン記録（何を・いつ変更したか） | `CHANGELOG.md`（該当バージョン、未確定なら `[Unreleased]`）          |
| 学び・判断基準（横断ルール）           | `.kiro/steering/`（該当ファイル）                                    |
| 学び・判断基準（パス連動）             | `.claude/rules/`（`.claude/rules/README.md` の書くタイミングに従う） |
| 委譲・還流の手順そのものの改善         | `.claude/playbooks/`（該当ファイル）                                 |
| 持ち越し事項（次にやるべきこと）       | `CHANGELOG.md` の `[Unreleased]`                                     |

判断基準の格上げは `.claude/rules/README.md`／`.kiro/steering/orchestration.md` の基準（実装が先・ルール化は後、1回限りは様子見・2回目で切り出す）に従う。バージョン記録・持ち越し事項はこの2回ルールの対象外——発生した時点で `CHANGELOG.md` へ書く。

## 書くタイミング（中間レポートとして書く場合）

- 1つのspec（またはタスクのまとまり）の実装が完了した直後
- 想定外の手戻りや、何度も同じ判断をやり直した箇所があったとき

## ファイル名

`YYYY-MM-DD-<feature-or-topic>.md`

## 手入れ（Garbage Collection）

- 恒久内容をすでに正本へ書き終えたレポートは削除してよい（正本側にリンクを残す必要はない）。
- `TEMPLATE-FEEDBACK:` マーカーの運用（`.claude/playbooks/template-feedback.md`）は本ファイルの改定と無関係に維持する。派生プロジェクトの振り返りに `TEMPLATE-FEEDBACK:` マーカーを付けて記録する運用は変わらない。
