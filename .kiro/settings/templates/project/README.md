このプロジェクトは AI エージェントと一緒に開発を進めます。あなたはプロダクトオーナー（PO）として、**何を作るかを決め、できたものを承認し、公開してよいかを判断します**。コードを書くのは AI です。

## いまどうなっているか

> [!TIP]
> [`STATUS.md`](STATUS.md) を開いてください。工程・承認待ち・止まっている作業・次にあなたがすることが1枚に載ります。手で書く欄はなく、`npm run status` で作り直されます。

## 始め方・進め方

Claude Code でこのフォルダを開き、次を入力します。あとは AI が順に質問します。

| やりたいこと                 | 入力する                         |
| ---------------------------- | -------------------------------- |
| 初めて使う（最初の設定）     | `/kiro-onboard`                  |
| 作りたいものを相談する       | `/kiro-discovery "やりたいこと"` |
| できたものを承認して次へ進む | `/kiro-approve <機能名>`         |
| いまの状況を聞く             | `/kiro-spec-status`              |
| 実装を進めてもらう           | `/kiro-impl <機能名>`            |
| プロジェクトを終える         | `/kiro-offboard`                 |

## 先に知っておいてほしいこと

> [!CAUTION]
> **AI だけでは越えられない場面が2つあります**。実地検証で確認されているもので、説明の丁寧さでは解消しません。
>
> 1. **技術的な回答が本当に妥当か**を、あなた一人では確かめられない場面。
> 2. **一度承認した2つのことが両立しない**と分かり、どちらを取るか決める場面。

> [!IMPORTANT]
> このため体制には **🧑🏼‍🏫 PO技術検証** という席が用意してあります。あなたの側に立って「本当に大丈夫か」を確かめる人の席で、既定では空席です。
> 技術的なことを相談できる人が身近にいるなら、その人に座ってもらうのが最も効きます。いない場合は AI で代替できますが、**その AI は開発側が用意するため、あなたの側の独立した確認にはなりません**——そのことは都度お伝えします。

詳しくは [`docs/team-structure.md`](docs/team-structure.md)、言葉の意味は [`docs/glossary.md`](docs/glossary.md) にあります。

## 決まりごと

- **公開（push）は必ず人間が実行します**。AI は勝手に外部へ出しません。
- **作る役とチェックする役は必ず別**にします。自分で作って自分で合格を出させません。
- 各工程（要件 → 設計 → タスク）は**あなたの承認**を通してから次へ進みます。承認は `/kiro-approve <機能名>` で行い、AI が中身を平易な言葉で要約し、気になる点を先に伝えたうえで可否を聞きます。1回につき1工程だけ記録します。承認した内容は記録され、**承認のあとに中身が変えられた場合は検査が検知して「要再承認」になります**。

## 先に知っておいてほしい設定と限界

> [!WARNING]
> **AI は多くの操作を、あなたに確認せず実行する設定が既定です**（作業のたびに許可を求めると進まないため）。危険な操作（外部への公開・強制削除など）は禁止リストと確認リストで止めますが、禁止リストは完全ではありません。
> この PC に、大切なファイルが git 管理の外にあるなら、AI に伝えて設定を安全側（毎回確認する方式）へ変えてもらえます。それはあなたが決めてよいことです。

> [!WARNING]
> **進行の采配は1つの AI（統括）に集中しています**。統括の誤りは別の AI のチェックで捕まえる仕組みですが、統括自身を外から常に見張る席（🧑🏼‍🏫 PO技術検証）は既定では空席です。
> 大きな判断の前に「本当に大丈夫か」を人間に確かめたいときは、その席に人を座らせることができます。
