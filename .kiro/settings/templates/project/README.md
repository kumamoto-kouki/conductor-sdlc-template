# （プロジェクト名）

このプロジェクトは AI エージェントと一緒に開発を進めます。あなたはプロダクトオーナー（PO）として、**何を作るかを決め、できたものを承認し、公開してよいかを判断します**。コードを書くのは AI です。

## いまどうなっているか

[`STATUS.md`](STATUS.md) を開いてください。工程・承認待ち・止まっている作業・次にあなたがすることが1枚に載ります。手で書く欄はなく、`npm run status` で作り直されます。

## 始め方・進め方

Claude Code でこのフォルダを開き、次を入力します。あとは AI が順に質問します。

| やりたいこと | 入力する |
| --- | --- |
| 初めて使う（最初の設定） | `/kiro-onboard` |
| 作りたいものを相談する | `/kiro-discovery "やりたいこと"` |
| いまの状況を聞く | `/kiro-spec-status` |
| 実装を進めてもらう | `/kiro-impl <機能名>` |
| プロジェクトを終える | `/kiro-offboard` |

## 先に知っておいてほしいこと

**AI だけでは越えられない場面が2つあります。**実地検証で確認されているもので、説明の丁寧さでは解消しません。

1. **技術的な回答が本当に妥当か**を、あなた一人では確かめられない場面。
2. **一度承認した2つのことが両立しない**と分かり、どちらを取るか決める場面。

このため体制には **🧑🏼‍🏫 PO技術検証** という席が用意してあります。**あなたの側に立って「本当に大丈夫か」を確かめる人**の席で、既定では空席です。技術的なことを相談できる人が身近にいるなら、その人に座ってもらうのが最も効きます。いない場合は AI で代替できますが、**その AI は開発側が用意するため、あなたの側の独立した確認にはなりません**——そのことは都度お伝えします。

詳しくは [`docs/team-structure.md`](docs/team-structure.md)、言葉の意味は [`docs/glossary.md`](docs/glossary.md) にあります。

## 決まりごと

- **公開（push）は必ず人間が実行します。**AI は勝手に外部へ出しません。
- **作る役とチェックする役は必ず別**にします。自分で作って自分で合格を出させません。
- 各工程（要件 → 設計 → タスク）は**あなたの承認**を通してから次へ進みます。

| `npm run verify` | 文書とデータの整合を検査する |

進め方の正本は [`.kiro/steering/`](.kiro/steering/)、AI への指示は [`CLAUDE.md`](CLAUDE.md) にあります。
