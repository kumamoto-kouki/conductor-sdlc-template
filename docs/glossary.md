# 用語集

このプロジェクトの文書に出てくる言葉を、前提知識なしで読めるようにまとめる。

## 進め方の言葉

| 用語                             | 意味                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| spec（スペック）                 | 機能ごとの仕様書。要件 → 設計 → タスクの順に固めていく。                                          |
| PDCA                             | 計画(Plan) → 実行(Do) → 確認(Check) → 改善(Act) のくり返し。                                      |
| コンダクター・オーケストレーション | 本プロジェクトの進め方の呼び名。取りまとめ役が作業を任せ、別の役がチェックし、証拠で受け入れる体制。 |
| worktree（ワークツリー）         | リポジトリの作業用の別コピー。同時編集の衝突を避けるために使う。                                  |
| push（プッシュ）                 | 手元の変更を共有サーバー（GitHub）へ反映＝公開する操作。人間だけが実行する。                      |

## テストと安全の言葉

| 用語                            | 意味                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------ |
| E2E テスト                      | End to End＝端から端まで。アプリを実際に起動して通しで動くか確かめる自動テスト。 |
| CSP                             | Content Security Policy。通信先や読み込み先を必要な範囲に絞るセキュリティ設定。 |
| semgrep（セムグレップ）         | コードの危険な書き方や脆弱性を自動で探すスキャナー。                           |
| happy-dom / insta / WebdriverIO | テスト用の道具。順に「画面部品の検査」「出力の固定検査」「実アプリ操作」。      |

テストの道具立ては実プロジェクトで採用したものの例であり、採用する技術はプロジェクトごとに [`.claude/playbooks/tech-selection.md`](../.claude/playbooks/tech-selection.md) の判断基準で決める。
